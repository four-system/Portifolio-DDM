## Questão 1 — Antes de desenvolver

Antes de começar a criar as telas no App Inventor, o grupo deveria planejar o aplicativo. Algumas informações importantes que deveriam ser definidas são:

1. **Objetivo do aplicativo:** definir qual problema o aplicativo irá resolver, nesse caso, ajudar os alunos a organizar trabalhos, provas e atividades escolares. Isso é importante para que o desenvolvimento tenha um objetivo claro.

2. **Público-alvo:** identificar quem irá utilizar o aplicativo, como alunos do ensino médio. Isso ajuda a decidir como serão os textos, botões e a organização das telas.

3. **Funcionalidades:** definir o que o aplicativo deverá fazer, como cadastrar atividades, visualizar tarefas, excluir atividades e organizar os compromissos.

4. **Interface e telas:** planejar quais telas serão necessárias e como os elementos ficarão organizados. Isso facilita a navegação e torna o aplicativo mais fácil de utilizar.

Também seria importante definir quais dados serão armazenados e quais recursos do App Inventor serão utilizados, como o TinyDB.

## Questão 2 — Funciona, então está pronto?

*Não concordamos com essa decisão.* O fato de o aplicativo ter funcionado uma vez não significa que ele esteja pronto. É necessário realizar vários testes para encontrar possíveis erros.

O grupo deveria verificar, por exemplo, se o aplicativo funciona quando o usuário deixa algum campo vazio, digita informações incorretas ou utiliza os recursos de uma maneira diferente da esperada. Também seria necessário verificar se os dados continuam salvos depois de fechar e abrir o aplicativo novamente.

Além disso, devem ser testados os botões, a navegação entre as telas, a exibição das informações e o funcionamento em diferentes tamanhos de tela.

Os testes são importantes porque permitem encontrar e corrigir problemas antes que o aplicativo seja disponibilizado para os usuários.

## Questão 3 — Mudanças fazem parte do desenvolvimento?

*Discordamos da afirmação.* Um aplicativo funcionar tecnicamente não significa que ele esteja completamente pronto.

Se os usuários não conseguem entender facilmente como utilizar o aplicativo, existe um problema de *interface ou experiência do usuário*. Nesse caso, mesmo que todas as funções estejam funcionando, é necessário fazer alterações para melhorar a utilização.

O objetivo de um aplicativo não é apenas executar seus comandos corretamente, mas também permitir que os usuários consigam utilizá-lo de maneira simples e clara. Portanto, o grupo poderia reorganizar os elementos, alterar textos, melhorar os botões ou modificar a navegação e depois realizar novos testes.

---

## Questão 4 — E quando alguma coisa dá errado?

O grupo não precisa recomeçar todo o projeto. É possível seguir um processo organizado para encontrar e corrigir o problema.

Primeiro, o grupo deve *identificar exatamente o problema*, verificando quais dados não estão sendo armazenados corretamente. Depois, deve tentar reproduzir o erro para descobrir em quais situações ele acontece.

Em seguida, deve analisar os blocos responsáveis pelo cadastro e pelo armazenamento no TinyDB, verificando, por exemplo, se a informação está sendo salva com a chave correta e se os dados estão sendo recuperados corretamente.

Depois de encontrar a causa, o grupo deve *corrigir os blocos* e testar novamente. Se o problema continuar, novos testes devem ser realizados até encontrar uma solução.

A sequência pode ser:

*Identificar o problema → Reproduzir o erro → Investigar os blocos → Corrigir → Testar novamente → Verificar se o problema foi resolvido.*
